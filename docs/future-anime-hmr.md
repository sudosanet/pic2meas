# 将来計画: イラスト向けの3D体型推定（InstantHMR の追加学習）

**状態**: 未着手。今のイラストモードは、次の2つで補っている。

- RTMPose（Human-Art）で骨格の点を取る。
- MHR の骨格スケールを絵の比率に当てはめる。

それでも誤差が大きく残る場合に着手を判断する。判断材料は `pnpm eval` の結果（下の「残っている誤差」）。

## なぜ必要か

InstantHMR は実写で学習されている。デフォルメされた体（大きな頭、短い胴、細い脚）では、体型パラメータの推定がずれる。骨格スケールの当てはめで比率は合わせられるが、次の2つは直せない。

- 頭の横幅などの形
- 服の下の体の厚み

## やり方: MHR の体から合成したイラストで追加学習する

正解の MHR パラメータが付いた絵は存在しない。そこで、正解が分かっている体から絵を作る（HumanWild と同じ考え方）。想定は4〜6週間・GPU 1〜4枚。置き場所は `tools/anime_hmr/`（Python、uv。デプロイ対象外）。

1. **体と姿勢を作る**
   - 体型（45次元）と骨格スケール（68次元）をサンプリングする。現実寸に加えてデフォルメ寄りの値も入れる（頭 140 番 0〜3、短い脚など）。
   - 姿勢は SAM 3D Body データセットの正解から取る（InstantHMR の `datasets_pipeline`）。
   - カメラの焦点距離は fit2 の `cliff` 条件と同じ決め方にする。
2. **条件画像を描く**: MHR メッシュから深度画像と OpenPose 形式の骨格画像を作る。
3. **イラスト化する**（diffusers）
   - アニメ系 SDXL（例: Animagine XL）と ControlNet（深度＋骨格）を使う。
   - 服装はプロンプトで振る（スカート丈、ワンピース、制服など）。
   - 2〜3万枚作る。1枚あたり約3秒なので、GPU 1枚で約1日。
   - 生成した絵で RTMPose を再検出し、元の骨格と合わないものは捨てる。
4. **学習データにする**: InstantHMR の window corpus 形式（288px、4種類の切り出し）に変換する。
5. **追加学習する**（`training/train_ddp.py`）
   - medium の PyTorch 重みから始める。
   - 合成イラストと元の実写データを 50% ずつ混ぜる（実写の精度を落とさないため）。
6. **書き出す**: 今と同じ入出力の fit2 グラフにして、`models/instanthmr-anime-medium-fit2-v1.onnx` として R2 に置く。
7. **評価する**
   - 合成データの検証分（MHR の正解あり）、`pnpm eval` の評価セット1・2、実写の 3DPW（劣化していないかの確認）で測る。
   - 実写が劣化しなければ両モードで使い、劣化するならイラストモードだけで使う。

## 採らなかった案

PEAR は採用しない。理由は次のとおり。

- ViT-H 級（約6億パラメータ）で、ブラウザでは重すぎる。
- SMPL / SMPL-X / FLAME（登録制で再配布できない）と pytorch3d が必要になる。
- 強みは頭と顔の形で、体の寸法の改善とは別の話。
